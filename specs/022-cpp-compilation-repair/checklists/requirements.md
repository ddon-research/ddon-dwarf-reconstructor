# Specification readiness: Compilation repair

This checklist evaluates the specification package, not implementation acceptance.

- [x] Reader, scope, prerequisites, and observed-versus-intended evidence are explicit.
- [x] Prioritized user stories have independently testable scenarios and negative cases.
- [x] Functional requirements and measurable success criteria cover fidelity and compilation.
- [x] Every functional requirement maps to tasks and validation tiers.
- [x] Existing typed models and graph algorithms are reused; no dependency is promoted.
- [x] Alias visibility, owner visibility, and complete definitions are separate requirements.
- [x] Nested shells, invented namespace/enum/template facts, and silent exclusions are rejected.
- [x] Doris preflight is current-state diagnosis, not unconditional destructive recovery.
- [x] Full versus probe reports and producer identities are separated.
- [x] Feature 021 ownership transfer and Feature 023 handoff preserve open acceptance obligations.
- [x] Constitution review requests no exception; performance and target-authority limits remain.
- [ ] Implementation tasks and final acceptance dimensions have passed on an identified producer.

Documentation lint/build outcomes are recorded in [measured evidence](../measured-evidence.md).
An unchecked implementation item is intentional; this checklist must not imply that writing
specifications repairs the code or validates the corpus.
